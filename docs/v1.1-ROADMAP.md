# iume-atelier v1.1 规划文档

> 基于 v1.0.0 上线实战（Netlify + Railway）整理 · 2026-06-06  
> 目标版本：**v1.1.0** · 定位：**生产可用 + 体验补全**

---

## 一、v1.0 上线复盘：发现了什么？

| 类别 | 现象 | 根因 |
|------|------|------|
| 部署 | Netlify 依赖安装失败 | `publish` 路径错误 + React 19 peer deps |
| 部署 | Netlify 构建设置冲突 | UI 与 `netlify.toml` 重复配置 base |
| 登录 | 403 Invalid CORS request | Railway 未允许 Netlify Origin |
| 登录 | 页面显示「密码错误」 | 前端把所有错误统一成一句 |
| 数据 | 线上只有 2 篇示例文 | 本地 MySQL ≠ Railway MySQL |
| 运维 | Railway 服务偶发 Error | 需看 Deploy log（内存/DB/健康检查） |
| 存储 | 上传图片重启后丢失 | Railway 磁盘非持久 |
| 功能 | `/search` 跳转到 `/articles` | PRD 规划未实现 |

**结论**：v1.1 优先解决「生产踩坑 + 用户可感知体验」，再做大功能（ES 搜索、Newsletter）。

## 五、本版本已开发内容（v1.1.0-alpha）

### 5.1 独立搜索页 `/search`

- 路由：`/search?q=关键词`
- 顶栏搜索「查看全部结果」跳转到 `/search` 而非 `/articles?q=`
- 保留 `/articles?q=` 兼容旧链接
- SEO：`PageMeta` 动态标题

### 5.2 登录错误提示优化

| 场景 | 新提示 |
|------|--------|
| 401 Bad credentials | 用户名或密码错误 |
| 403 / CORS | 跨域被拒绝，请检查后端 CORS 配置 |
| 网络超时 / 502 | 无法连接服务器，请稍后重试 |

### 5.3 生产 CORS（后端）

`application-prod.yml` 默认：

```yaml
allowed-origins: https://*.netlify.app,https://*.vercel.app,http://localhost:5173
```

`CorsConfig` 支持 `*` 通配 pattern。

## 六、对象存储（✅ v1.1.1）

**问题**：Studio 上传封面/正文图片到 Railway 本地磁盘，重启后 404。

**实现**：`FileStorage` 策略 + `UploadService` 委托存储：

| 环境 | 策略 |
|------|------|
| 本地 dev | `LocalFileStorage` → `uploads/` + `/api/uploads/**` |
| prod + R2 | `S3FileStorage` → Cloudflare R2，返回公网 URL |

**环境变量**：

```env
IUME_STORAGE_TYPE=local|s3
IUME_S3_ENDPOINT=https://xxx.r2.cloudflarestorage.com
IUME_S3_BUCKET=iume-atelier-uploads
IUME_S3_ACCESS_KEY=...
IUME_S3_SECRET_KEY=...
IUME_S3_PUBLIC_BASE_URL=https://pub-xxx.r2.dev
```

详见 [deploy/R2-SETUP.md](../deploy/R2-SETUP.md)。

## 八、Railway 服务 Error 排查手册

截图里 **iume-atelier Error** 时按顺序查：

1. **Deployments → 最新日志**
   - Flyway 失败 → MySQL 变量名/连接
   - OOM → 升级 plan 或减 JVM 内存
   - Port 不对 → Spring Boot 默认 8080
2. **Variables** 是否齐全：`SPRING_PROFILES_ACTIVE=prod`、JWT、MySQL 引用
3. **MySQL 服务** 是否 Online
4. 手动 **Redeploy**
5. 验证：`/api/health`
